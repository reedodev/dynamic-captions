# 구현 메모

## 구조
- `scripts/runtime.js`는 브라우저에서 도는 파일 하나입니다. 화면은 시간 `t`만의 함수입니다(`window.seek(t)`). 그래서 프레임 구간을 여러 Chrome에 나눠 맡겨도 결과가 같습니다.
- `render.mjs`가 Chrome(CDP)으로 투명 PNG를 프레임마다 저장하고 ffmpeg로 영상에 겹칩니다.
- 렌더러 계약: `window.ready`, `window.DURATION`, `window.seek(t)`, `window.visible(t)`, `window.bounds()`, `window.posRect()`, `window.phraseStats()`, `window.sizeScan()`, `window.fontCoverage()`, `window.styles`.

## 새 스타일 추가
`runtime.js`의 스타일 라이브러리에 다음 모양으로 넣으면 시안에 자동으로 포함됩니다.

```js
S['my-style'] = {
  label: '이름',
  group: { maxChars: portrait ? 10 : 20, maxWords: 4 }, // 한 묶음의 한도
  slack: 1.1,   // 등장 애니메이션이 커지는 배율(자리 여유 계산에 씀)
  fill: 2.4,    // (선택) 이 배율까지 키워 폭을 채움
  build(ph, el, mix) { /* DOM 만들기, ph.els에 단어 요소를 담음 */ },
  update(ph, t) { /* t초의 모습 */ },
};
```

정지 화면에서 먼저 읽히는지 확인하고(움직임이 글자를 구해 주지 않습니다), 한 화면에 강조는 하나만 둡니다.

## 자동 점검 값
- 글씨 크기 하한: 1080p 가로 40px, 1080×1920 세로 50px. 하한 아래로 줄어들면 같은 높이대의 넓은 자리로 옮깁니다.
- 안전 구역: 가로는 아래 22%, 세로는 아래 약 30%·위 10%·오른쪽 10% 비움. 자막이 자기 자리 밖으로 나가면 렌더를 멈춥니다(`--allow-overflow`로 무시).
- 얼굴: 문장이 나오는 동안(앞뒤 0.5초) 보인 얼굴과 글자 상자가 2% 넘게 겹치면 다른 자리를 시도합니다.
- 읽기 속도: 묶음별 초당 글자 수(공백 제외). 17 초과 빠름, 25 초과 위험(외국 저장소의 기준값이라 한글은 참고용).
- 박자 펄스: 박마다 1.045배로 커졌다가 0.4초 안에 돌아옵니다(`--beat-strength`).

## 시험으로 확인한 것
- 병렬 렌더: 같은 15초 구간을 워커 1개와 4개로 만들어 비교했을 때 프레임 수가 같았고 PSNR 55.7dB로 거의 같았습니다. 1080p 75초는 197초 → 64초.
- 한국어 랩 가사: 받아쓰기만으로는 철자가 많이 틀리고(예: 문 앞 우산꽂이에 → 문화 부산 꼬지에), 가사 대본으로 철자를 맞추면 일치율 94.4%였습니다. 가사와 소리가 다른 12곳은 사람이 들어 확인해야 합니다.
- 얼굴 찾기: 같은 정지 그림에서 OpenCV Haar는 51%, YuNet은 100%.
- 박자: 88BPM으로 알려진 랩에서 힌트를 주면 89.1BPM, 신뢰도 0.94.
- 처음 쓰는 사람 시험(AI가 설명서만 읽고 따라 함)에서 시안은 통과하는데 최종 렌더가 구역 경고로 멈추는 문제가 나와, 시안이 모든 문장을 검사하도록 고쳤습니다.

## 한계
직접 들어 보지 못합니다. 한국어 강제 정렬이 없어 랩 단어 시간은 거칩니다(단어 하나 최대 1.8초로 제한). 얼굴은 정면 사람 얼굴만 찾고 몸·소품은 피하지 않습니다. 사람 뒤에 글자를 넣는 효과와 스크램블 효과는 없습니다.

## 1.1.0 (새 스타일 23개)

- 감정·의성어 7, 배치 7, 장식 9. 등장 속도 자동 단축(문장 표시 시간 중앙값 기준), mix 감정 단어 배정(최대 4번, 3초 간격), duo-tight 행간 옵션(`--line-ratio`, `--line-gap`).
